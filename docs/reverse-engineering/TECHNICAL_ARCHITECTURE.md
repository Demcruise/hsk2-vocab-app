# Technical Architecture — As-Is

## PWA (`index.html`)

Single document: ~650 lines CSS, ~200 lines markup, then 4 inline scripts plus `hanzi-writer.min.js` and an ES-module sticker bundle.

### Script layout

| Lines | Content |
|---|---|
| 926–928 | Inlined data: `VOCAB_DATA` (HSK2, 1.17 MB on one line), `RADICALS_DATA`, `HANZI_DATA` |
| 930–1136 | Original app: state `S`, TTS, persistence, flashcards, first-generation quiz, vocab/known lists, radicals, stats, achievements, hanzi tooltip, screen switching, theme |
| 1138–1222 | HSK1 data (`HSK1_VOCAB_DATA`, 307 KB), `UNIT_DEFS`, `LEVELS`, level switching, unit/learning path, sessions, rail, confetti |
| 1223–1741 | Second-generation features: stroke data loader, speaking (ASR), writing, typed MC exercises (`Q_MIX`), quiz picker, practice hub, stories |
| 1742+ | `// ===== OVERRIDES =====` — reassigns earlier functions (`hzShow`, `renderLearnPath`, …) |

Function redefinition is used as an extension mechanism: `startQuiz`, `showQ`, `checkAns` each have two `function` declarations (hoisting means the **last** one wins), and several more are reassigned at the end. This makes the effective behaviour of any function hard to know without reading the whole file.

### State and persistence

- One global mutable object `S` (session, quiz and persistent fields mixed together).
- Persistence: `localStorage[storeKey()]` where `storeKey()` = `khsk1` | `khsk2`; plus `khsk-level`, `khsk2-theme`, `khsk-expinyin`.
- Stored schema (short keys): `p` per-word progress `{l: 0..3, c, w, t, ml, ms, mw}`, `s` streak, `l` last-active date string, `x` XP, `q` quizzes, `a` achievements, `k` known set, UI fields (`sc`, `md`, `vf`, `kf`, `wid`, `sa`).
- `progressPayload()` (export) additionally contains `v:2`, `st` (stories done) and `ld` (lessons done) — **`saveState()` does not**, see K-01.
- No schema version in localStorage payload, no migrations.

### Rendering

String-concatenated `innerHTML` per screen (`renderX()` functions), global event listeners, `switchScreen()` toggles `.screen` classes. No component model, no router (no deep links).

### Domain coupling

Learning logic (scoring in `resolveQ`, levels in `rateCard`, lesson state in `lessonState`) directly manipulates DOM, plays SFX and calls `saveState()`. There is no UI-independent learning domain module, so unit tests can only run in a browser.

## Flutter (`mobile/lib`)

```
data/models.dart     VocabWord, Sentence, RadicalEntry, Unit, Lesson
data/content.dart    JSON asset loading, unit building, pinyin helpers
data/app_state.dart  ChangeNotifier — progress, streak, XP, known, achievements, per-level keys (same as web)
data/services.dart   TtsService, SfxService, BackupService
ui/*.dart            Screens (learn, session, quiz, vocab, radicals, progress, story, writing, speaking)
```

Cleaner separation than the PWA (models + state outside widgets), `AppState` persists `st`/`ld` correctly. Same scoring rules duplicated in Dart — two implementations of every rule that must be kept in sync by hand.

## Data pipeline

PDF → `tools/extract_hsk1.py` (pypdf; hard-coded absolute paths) → `hsk1_data.json`; sentences generated by `generate_sentences.mjs` / `full_generator.js`; English translation chunks → `tools/apply_en.mjs` splices into `index.html` and Flutter assets; topics via `tools/assign_topics*.mjs`. No validation step runs automatically.

## Architecture options (for Phase 5 decision)

| Option | Description | Pros | Cons |
|---|---|---|---|
| A. Incremental | Keep single-file PWA, fix bugs, add features in place | Zero migration risk, fastest | File already 1.7 MB / override chain; HSK 3–9 data (~11k words × sentences) cannot be inlined; untestable domain logic |
| **B. Modular refactor (recommended)** | Keep vanilla PWA + no-framework UI, but split into ES modules: `domain/` (pure, unit-tested: scoring, SRS, streak, unlocks), `content/` (per-level JSON loaded lazily), `ui/`; add a tiny build (esbuild, already used for stickers) | Preserves behaviour and deployment, enables tests + lazy content, smallest real fix | Needs careful extraction with regression tests first |
| C. Migrate | Make Flutter the single client (web + Android), retire PWA; or move PWA to a framework | One codebase | Large rewrite, Flutter web bundle heavy (canvaskit), loses working PWA; high risk |

Recommendation recorded for review: **B**, and decide separately whether to keep two clients or freeze Flutter until the domain is stable (duplicated logic is the main cost).
